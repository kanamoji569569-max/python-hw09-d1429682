## 一、程式用途與執行方式

本程式用於整理「桌遊體驗」與「電影欣賞」兩場活動的文字報名資料。程式先清除原始字串中的半形空白並統一轉為小寫，保留原始順序建立 `list`，再透過 `set` 去除重複報名並計算交集、聯集與雙向差集，最後以 `dict` 統整各場人數、總不重複人數、報名人次及應收費用。

## 三、個人回答

1. **問題一：測試一中，整理後的桌遊串列有 4 筆資料，為什麼桌遊費用應以 3 人計算？直接把字串拆成 list，和再轉成 set，各自保留了什麼、失去了什麼？**
   - 因為 `" Amy"` 與 `"amy"` 整理後都是同一位參加者 `amy`，依規則同一人在同一場活動重複報名只算一位參加者、只收一次費用，所以桌遊實際有效人數為 3 人（`3 × 120 = 360` 元）。
   - 直接拆成 `list` 時，**保留了**原始報名先後順序與重複報名的筆數紀錄，但**失去了**快速排除重複項目的特性；轉成 `set` 後，**保留了**不重複的唯一參加者集合並可直接做交集、聯集與差集運算，但**失去了**原本的報名順序以及重複出現的次數資訊。

2. **問題二：測試三中，兩場活動只有 3 位不同的人，為什麼是 6 人次、總應收仍是 600 元？請用集合關係與算式說明。**
   - 測試三中，桌遊集合 $B = \{\text{'amy'}, \text{'ben'}, \text{'cora'}\}$，電影集合 $M = \{\text{'amy'}, \text{'ben'}, \text{'cora'}\}$。兩者聯集 $B \cup M$ 只有 3 個不重複元素（總不重複人數為 3 人），但交集 $B \cap M$ 也有 3 人，代表這 3 位參加者同時報名了兩場活動。
   - 依規則兩場活動分別計費且參加兩場算兩人次，因此報名人次為 $|B| + |M| = 3 + 3 = 6$ 人次；總應收則為 $(3 \times 120) + (3 \times 80) = 360 + 240 = 600$ 元。
